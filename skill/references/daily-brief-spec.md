# 日报完整规格

每天生成一份中文「开发者趋势速报」，目标是在 5 分钟内帮助我跟上真正重要、且可能动手使用的技术动态，并把完整日报追加到已发布的 Sites 网站。

关注方向按优先级筛选，不要求每天每类都凑数：
1. 扩散模型、图像/视频生成、生成式视觉模型、工作流与推理加速；
2. 图像超分辨率、修复、增强、去噪、插帧，以及相关训练/评测工具；
3. VHDL、Verilog/SystemVerilog、FPGA、软核、EDA、开源综合/仿真/验证工具和硬件加速；
4. 能部署到个人电脑或手机的工具，尤其是离线、本地优先、消费级 GPU/CPU/NPU 可运行的开源项目；
5. 具身智能，包括机器人基础模型、VLA、模仿学习/强化学习、世界模型、仿真、遥操作、数据采集与数据集、低成本机器人硬件，以及能真实复现或部署的开源项目；
6. LLM 与 Agent 工程，包括 LangChain、LlamaIndex、CrewAI 等框架，以及 RAG、工具调用、MCP、Agent 评测、追踪、记忆与可靠性；
7. 本地 LLM 推理与服务，包括 vLLM、llama.cpp、Ollama、量化、推测解码、CPU/GPU/NPU/WebGPU/移动 DSP 后端和端侧部署；
8. AI 编程与自主编码 Agent，包括 Aider、OpenCode、Codex、编辑器集成、代码审查、工作区隔离、权限与失败恢复；
9. 开发者效率工具，包括 CLI、终端、Shell、模糊搜索、代码检索、版本/环境管理，以及值得自托管的开源替代品；
10. 系统与底层工程，包括 Rust/Go 生态、异步运行时、Kubernetes/etcd、Redis/SQLite、存储、网络、数据库内核和高性能系统；
11. 体系化学习与精选资源，包括有实质新增的 awesome-*、源码精读材料、系统设计与基础内功资源。精选列表只作为候选入口，不能把“被收录”当成技术背书。
12. 好玩的小项目、小游戏和互动网站：浏览器即玩小游戏、可离线的电脑/手机小游戏、物理沙盒、自动化/建造、数字逻辑/电路解谜、创意编程/生成艺术、互动可视化、桌面小玩具等。优先低门槛、有实际可玩入口、开源或运行方式透明的项目，也可收录有趣但未开源的在线网站，必须明确区分。

研究流程：
先浏览 GitHub Trending（https://github.com/trending），以 Daily、All languages 为入口，但不要受榜单限制。主动搜索以上方向过去 24–72 小时的新仓库、Release、关键提交、论文实现、模型权重、性能更新与重要讨论。优先查看 README、Release、提交记录、论文、模型卡、项目官网和官方公告等一手来源。检查已有日报，尽量避免连续多天重复；若重复，必须明确说明相较上一期的新增进展。若当天没有足够重要的新内容，宁可少写，并把近期但非当天发布的内容明确标注为“非今日发布”。技术新闻中的经典项目只有在这段时间出现实质发布、安全/性能变化或很有学习价值的源码改动时才收录。趣味发现是例外：先找过去 24–72 小时的新项目或实质更新；若没有足够新内容，可从未推荐过的经典项目中精选，并标注“趣味发现 / 非今日发布”，不能伪装成当日热点。

分类规则：
1. 保留网站已有的图像生成、超分辨率、FPGA/VHDL、具身智能等技术点分类，不得合并、覆盖或改名为宽泛大类。
2. 所有新增内容也必须按具体技术点分类，不得使用“AI / Agent”“效率工具”“系统工程”“行业前沿”这类宽泛标签。
3. 分类粒度参照：Agent 框架、本地 LLM 推理、LLM 推理服务、编码 Agent、AI 编程编辑器、CLI / 终端、Python 工具链、开发环境、异步运行时、自托管 Git、自托管相册、云原生 / Kubernetes、数据库内核 / WASM、精选资源 / Go。按项目实际技术点选择，不必拘泥于示例。趣味内容也拆成具体玩法/技术点，例如“电路解谜 / 数字逻辑”“物理沙盒 / 元胞自动机”“本地游戏 / 工厂塔防”“浏览器游戏 / 迷宫解谜”“创意编程 / 生成艺术”“桌面小玩具 / 像素动画”，不要统一归为宽泛的“趣味”或覆盖原技术分类。
4. 分类筛选按钮继续从 reports.js 动态生成，并直接对应这些技术点；不要另加覆盖旧分类的上层大类。

日报内容：
1. 今日一句话：概括最明显的趋势。
2. 今日最相关：主技术速报精选 5–10 个真正有信号的项目或事件，仍以约 5 分钟掌握重点为目标；另附可选阅读的趣味加餐，广泛搜索好玩网站、小项目和本地/手机小游戏，通常精选 3–6 个，用户要求扩充时可以一次补更大的合集，不受主技术条数上限限制。好玩本身可以构成推荐理由，不必强行附会学习或生产力价值；方向不足时宁可少写，不每日凑数。技术项说明它是什么、为什么现在值得关注、适合谁、部署或采用门槛，并附原始链接。趣味项用更轻松的语言说明怎么玩/好玩在哪里、建议体验时长、在线即玩或官方下载链接、桌面/手机与输入方式、能否离线、是否需账号/收费/联网及已知限制。开源项目附仓库与许可证；源码未开放或授权未确认则直说，不把浏览器能玩等同开源或离线。
3. 本地部署雷达：尽量注明系统、典型硬件、显存/内存、量化、许可证和安装成熟度。
4. FPGA/VHDL 雷达：仅在有实质性新内容时输出，关注器件支持、工具链、综合/时序/资源数据及复现条件。
5. 具身智能雷达：仅在有实质进展时输出。说明机器人平台、传感器、算力、代码/权重/数据开放情况与真实机器人验证；严格区分仿真和实体结果。
6. Agent 与开发工具雷达：关注评测、追踪、权限、隔离、回滚、成本、失败恢复和跨平台成熟度，不把演示当可靠性证据。
7. 系统与底层雷达：优先实质 Release、安全/兼容变化、可测性能改进和有学习价值的源码提交，不用普通依赖更新凑数。
8. 今日深挖：选一个最有长期价值的项目或技术，说明核心方法、差异、局限和建议的下一步。
9. 信号与噪音：指出一项可能被高估的热点，明确这是判断而非事实。

网站更新流程：
1. 更新本机站点 E:\VHDL\future-tech-dashboard。
2. 把当天内容作为一条新的日报记录添加到 dist/reports.js 的最前面，保留全部历史记录。若当天日期已存在，更新该记录而不是新增重复日期。
3. 保留现有网站设计、搜索、技术点分类筛选和历史记录。不得恢复“全部日期”视图，也不得退回只显示最新一期的版本。
4. 首页默认显示最新周视图。底部必须保留由 reports.js 动态生成的单日、周视图、月视图、年视图。周按周日到周六分组；只显示实际包含日报的日期或周期。
5. 单日视图显示该日完整指标、今日一句话、项目、深挖和信号与噪音。周/月/年视图聚合所选周期内的日报与项目（包括趣味加餐），每张卡标注所属日期，聚合指标只统计当前周期，并显示该周期最新一期的深挖与判断。
6. 分类筛选和关键词搜索必须只作用于当前选中的日期或周期。新增日报后，日期/周期选项、技术点分类和计数必须自动更新，无需手工维护。
7. 每次更新后验证：当天记录位于最前、历史仍在、没有“全部日期”入口、默认最新周正确、单日/周/月/年切换正常、旧技术点分类仍存在、新分类粒度足够具体、搜索与脚本语法有效。
8. 按 Sites 建站与托管流程发布更新，复用 .openai/hosting.json 的现有 project_id，不创建新站点，并保持现有访问范围。
9. 确认部署成功后，发送精简摘要和站点链接 https://future-tech-radar-daily.jdh020684.chatgpt.site 。

质量要求：
信息必须新鲜并带可点击的一手来源；区分事实与推断；不得仅凭 stars 判断价值。具身项目不得只凭演示判断，应优先关注可复现性、真实机器人测试、数据开放程度和硬件成本。Agent 项目不得只凭自主化演示判断，应核对权限、隔离、评测和失败恢复。精选列表的新增条目必须回到原仓库核验后再决定是否重点推荐。
趣味推荐质量要求：避免连续重复、下载站套壳、侵权移植、强制索取敏感权限、挖矿/博彩与未经说明的付费门槛；只给官方可玩页/仓库/发行渠道。网页不可用或只能看到演示时明确标注；未实际试玩不得声称试玩成功。娱乐玩法不必强行套 AI/FPGA 标签，但与数字逻辑、物理模拟、自动化和本地部署的自然交集可优先。维护存档/隐私提醒，浏览器本地存储可能被清除；不要为了试玩安装软件、开端口或授权账号。
趣味内容与主技术速报分清时效和阅读预期：经典发现标注“非今日发布”，每项用简短玩法、体验时长、平台/输入方式、费用和官方入口帮助我快速选择。首页计数要能涵盖全部条目，不把娱乐条目误称为技术突破；仍按具体技术/玩法细分类，不加覆盖旧分类的宽泛大类。页面为游戏卡保留在线玩/官方下载以及源码链接（有源码时），并检查新增卡片在日期、分类、搜索中的行为。
