## InvokeAI 优化 INT8 权重从内存搬到显卡的路径

**图像生成 / 推理加速 · NOV 01 MAIN · 北京时间**

10:25 合入：对适用的 INT8 权重，先以压缩格式从 CPU 传到 GPU，再在显卡上转换计算精度，减少部分卸载模型时的数据传输。

适合显存装不下完整模型、需要 CPU 内存辅助的生图用户。作者 Windows / RTX 4090 的一组 Krea-2 Turbo、1024²、8 步测试中，24% 常驻显存时从 56.5 秒降到 20.2 秒；这是特定模型与配置，非通用提速。适用 tensorwise / convrot INT8 路径，模型完全常驻显存时路径不变；作者称输出像素一致，峰值预留显存可能略增。Apache-2.0 代码，权重许可另查；主干更新，本机未复现。与昨日 FLUX.3 模型接入是不同改动。

INT8 · CPU / GPU 卸载 · 4090 单组：56.5 → 20.2 秒 · 速度与显存取决于模型和总线

## Verilator 减少超大嵌套循环展开的编译开销

**FPGA / SystemVerilog 仿真 · NOV 01 MAIN · 北京时间**

21:35 合入循环展开优化：在已知循环下标时更早判断展开限制，避免为复杂嵌套循环建立大量最终不会保留的中间语法树。

适合编译含大型循环的 SystemVerilog 验证环境。作者给出的一个案例中，V3Unroll 阶段由 10.4 秒降到 0.61 秒，整体由 61.2 秒降到 50.8 秒，生成代码相同；具体收益取决于设计和展开设置。这是本地 CPU 编译性能，不能当成 FPGA 时序或仿真运行速度提升；LGPL-3.0 / Artistic-2.0。本次是继昨日嵌套循环常量替换正确性修复之后的新性能改动。

## 今日深挖：本地生图为什么会卡在显存与内存之间？

显存不足时，生图工具可能把部分权重留在 CPU 内存，需要使用时再搬到显卡。InvokeAI 此次对部分 INT8 路径调整顺序：先搬运压缩权重，再在 GPU 上转为计算精度，从而减少 PCIe 上传的数据量；完全常驻显存的模型不会获得同样收益。作者在 RTX 4090 的特定 Krea-2 Turbo 测试中，24% 常驻时 56.5 秒降到 20.2 秒，而另一台 AMD 显卡、不同常驻比例的收益较小；不能按此保证任何机器的速度。作者称结果像素一致，峰值预留显存可能略有增加，其他量化路径也不一定受益。建议固定模型、分辨率、步数和种子，记录生成时间、系统内存与峰值显存，再比较升级前后图像；核对模型权重许可。该提交尚未在本机复现。
