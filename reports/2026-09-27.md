## Embodied.cpp

**具身智能 · HIGH SIGNAL**

面向 VLA 与世界—动作模型的 C++ 推理运行时，支持 CPU、CUDA、NPU 和 GGUF。9 月新增 Xiaomi-Robotics-0、TurboVLA 与 X-VLA，并提供 LIBERO 评测。

像具身智能领域的 llama.cpp：重点不在发布另一个模型，而在让现有模型更容易量化、部署和比较。

Apache-2.0 · Q4–Q8 · CPU / GPU / NPU

[原始来源](https://github.com/SEU-PAISys/Embodied.cpp)

## MFLUX

**图像生成 · DEPLOYABLE**

Apple MLX 原生的图像与视频生成工具链，覆盖 FLUX.2、Z-Image、Qwen Image 2.1、Ming-Image，并可用 SeedVR2 做超分。

对 M 系列 Mac 用户，这是绕开 CUDA 重型环境、快速尝试新视觉模型的实用途径。

Apple Silicon · 量化 · LoRA / ControlNet

[原始来源](https://github.com/mflux-community/mflux)

## Nightmare Mobile

**移动部署 · EXPERIMENTAL**

在 Android 手机上运行的节点式图像工作流，支持文生图、局部重绘、超分、FLUX.2、Z-Image 与视频生成，计算由高通 Hexagon NPU 完成。

端侧生成正在从单一按钮应用走向可组合工作流，但高端 Snapdragon 门槛和非商业许可证需要注意。

Android 12+ · Snapdragon · CC BY-NC 4.0

[原始来源](https://github.com/AbrahamPaulJ/nightmare-mobile)

## fast-rtxvsr

**超分辨率 · BENCHMARKED**

面向 Windows RTX 显卡的视频超分 CLI，解码、VSR 与编码全程留在 GPU，避免 PNG 往返和额外服务器。

作者在 RTX 5060 Ti 16GB 上报告 768×1344 到 1080×1920 约 26.7 fps，适合实际批处理。

Windows · NVIDIA RTX · CUDA / VFX

[原始来源](https://github.com/glarsson/fast-rtxvsr)

## OpenCircuitX

**FPGA / VHDL · WATCH**

把 VHDL/Verilog 编辑、GHDL 仿真、波形、RTL 视图和 FPGA 工具链收拢到一个桌面应用，Windows 已提供安装包。

目标是降低开源 FPGA 工具链的使用门槛；当前重点器件为 iCE40 与 ECP5，成熟度仍需实际项目验证。

MIT · Windows · iCE40 / ECP5

[原始来源](https://github.com/openlab-x/OpenCircuitX)

## OpenJLS

**FPGA / VHDL · VERIFIED**

开放的 VHDL JPEG-LS 无损编码器 IP，强调跨厂商综合，并以独立参考编码器进行逐字节验证。

相比只展示波形或板上演示的项目，它把验证报告和工具链依赖写得更完整，适合评估图像链路硬件加速。

VHDL · JPEG-LS · 多工具链

[原始来源](https://github.com/isentropic-fpga/OpenJLS)

## mise v2026.9.15

**开发环境 / CLI · SEP 27 RELEASE**

多语言版本、任务与环境管理工具开始把 vfox 安装的工具打进 OCI 镜像，并显著缩短 shell prompt、cd 与设置加载路径；dotfiles 的 include/exclude 改为更接近 .gitignore 语义，修复回滚可能误删活动文件的边界情况。

它适合替代一部分 nvm、pyenv、asdf 与零散任务脚本，但功能面很宽，配置错误也会影响整个开发环境。该版改变任务校验与模式匹配行为，升级前应运行 mise doctor 和任务验证，在测试目录演练 dotfiles capture/rollback，并固定团队使用的插件来源。

MIT · Windows / macOS / Linux · 工具版本 + 任务 + 环境

[原始来源](https://github.com/jdx/mise/releases/tag/v2026.9.15)

## Starship：Jujutsu VCS 状态进入提示符

Starship 主分支为 vcs 模块加入 Jujutsu 支持，并修复指向仓库子目录的符号链接渲染及 Nim 项目目录检测；更新面向高频 shell 提示符，而不是新增独立命令。

## 今日深挖：今日深挖 · Embodied.cpp

具身模型正在经历与早期大语言模型相似的阶段：研究代码能跑，但部署环境碎片化、显存需求高、不同实现难以公平比较。Embodied.cpp 的价值在于把 VLA 与世界模型转换为 GGUF，并为多种模型提供统一的 C++ 运行时和评测边界。它报告的延迟与显存下降很有吸引力，但目前主要证据仍来自标准基准和项目演示；真实机械臂的控制频率、传感器同步、安全停机及跨平台迁移仍需要单独验证。建议先用 LIBERO 或 RoboTwin 复现实验，再决定是否接入实体硬件。

[查看原始项目](https://github.com/SEU-PAISys/Embodied.cpp)
