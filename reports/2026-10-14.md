## Yosys 0.70：mcm 将常数乘法改写为共享加法图

**FPGA / 综合优化 · OCT 13 RELEASE · 非今日发布**

新增 mcm pass，把常数乘法单元改成共享的移位、加减网络；同时加入实验性 optbarriers、flatten/prep 的 barriers 选项，并移除 read_xaiger2。对 FIR、定点 DSP 和硬件加速的数据通路设计，值得专门做一次资源对照。

## GHDL：带前导零的负整数不再被 TEXTIO 读成正数

**FPGA / VHDL · OCT 14 MAIN BRANCH · TEXTIO 修复**

INTEGER READ 改为单独记住负号，避免 -012、-00012 等输入在累积遇到零后丢失符号；仍保留负向累积以支持 integer'low。新增 VHDL 2008/2019 下两个 READ 重载、边界值与剩余文本的回归用例。

适合从文本喂入定点测试向量的 VHDL 用户，这是会影响期望值的正确性问题。GPL-2.0，CPU 本地仿真，无 GPU 要求；当前是主分支，不代表已进入你安装的稳定包。更新时要确认使用新构建的标准库，重跑含负数和前导零的数据集。此修复与 FPGA 器件支持、综合资源及板上时序无关。

GPL-2.0 · VHDL 2008 / 2019 · std.textio · 主分支 · 标准库需匹配

[原始来源](https://github.com/ghdl/ghdl/commit/1e3c5ab06c9f712a52e343c7eb935a5623d42513)

## LeRobot：G1 + SONIC 给出远程推理与动作断粮契约

**具身智能 · OCT 14 MAIN BRANCH · G1 远程推理**

新增 Unitree G1 的 SONIC 配方：GPU 主机运行策略服务，G1 Jetson 保留解码器及 50Hz 底层控制，交换 64 维动作 token；等待时重发完整 token，首包前使用解码器中性 token 而非全零。与昨日 Lance 数据读取优化不同，这是 rollout 部署能力。

维护者称配方经过硬件验证，但没有新任务成功率、跨网络延迟统计或成本清单。公开代码/配置及 nepyope/sonic_walk 权重引用可查，代码 Apache-2.0，权重与数据许可另核对；需 G1、Jetson、头部 RGB 相机及 CUDA GPU 主机，未给最低显存。示例仅容许动作缓冲断粮后保持最多 1 秒，随后故障退出；原始关节/其他 locomotion 控制器仍不支持。文档禁止把 token 插值当作安全回位，不能把这套接口等同于实机安全认证。

Apache-2.0（代码） · G1 / Jetson + GPU 主机 · RGB · 维护者报告实机验证 · 非安全保证

## 今日深挖：Yosys mcm：把常数乘法看成可共享的数据流图

事实：0.70 的 mcm 将常数乘法改写成共享移位/加减图，默认最大加法深度为 3，并提供最小估算收益和搜索预算选项。直观上，同一个 x 的多个常数倍可以复用中间结果，而非各自独立实现；这对 FIR 系数组尤其值得试。判断：长期价值在于把算术重构变成可复现的编译优化，而不只是手写移位技巧。局限：加法数量只是代价模型，真实器件还有 DSP 映射、扇出和布线代价，较少的算子未必带来更高 Fmax。下一步：挑一个已有定点 FIR，固定位宽、截断/溢出语义、器件和时钟，保留原流程与 mcm 对照；先做等价验证，再比较 LUT/FF/DSP、关键路径和布局布线结果，改变 depth 检查面积与时序的取舍。本期没有可核验的跨器件收益百分比，不补想象数字。
