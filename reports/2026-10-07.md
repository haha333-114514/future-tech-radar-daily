## Kandinsky 6：同步视频与 44 kHz 音频的消费卡路径

**音视频生成 · OCT 06 OPEN SOURCE**

新公开的 3B Lite 与 29B Pro 扩散模型可生成 5 秒同步音视频，支持文生音视频、图生音视频，并通过独立超分模块输出 1920×1080；仓库给出 RTX 4090、5060 Ti、5080、5090、A100 与 H100 的预设和基准。

消费级 GPU 确实进入官方支持表，但离实时很远：官方热启动测试中，RTX 4090 生成 Lite Full HD 约 578 秒、Pro Full HD 约 1,247 秒，且不含载权重与 MP4 编码。要求 NVIDIA GPU、Python 3.13/3.14、CUDA 13；Ampere/Ada/消费级 Blackwell 还需本机 nvcc 编译 SageAttention。代码为 MIT，下载权重前仍应单独核对模型卡许可。

MIT（代码） · NVIDIA GPU · CUDA 13 · 3B / 29B · 5 秒音视频

[原始来源](https://github.com/kandinskylab/kandinsky-6)

## text-to-cad v0.7.15：给编码 Agent 一个可检查的 CAD 执行层

**CAD 自动化 · OCT 06 RELEASE · DAILY TRENDING**

本地工具让 Claude Code、Codex、Cursor、Gemini 等 Agent 通过插件或 MCP 生成 STEP、GLB、STL、3MF，并提供参数化几何、DFM 检查和工程图。v0.7.15 增加封闭网格的圆角扫掠茶杯示例，并收紧按影响范围运行的 CI 与发布分支安装流程。

它的价值不是保证一句话得到可制造零件，而是把 Agent 生成的 Python/几何操作落到 OpenCASCADE 与 build123d 的确定性执行链上。需要 Python 3.11+、Node.js 20+，首次运行会联网下载运行时；尺寸、公差、封闭性和 DFM 结果仍必须人工或脚本复核。

MIT · Python 3.11+ · Node 20+ · STEP / STL / 3MF · MCP

[原始来源](https://github.com/earthtojake/text-to-cad/releases/tag/v0.7.15)

## Power Intent Studio：把 RTL 层级与 UPF / CPF 放到同一张图上

**EDA / 低功耗设计 · OCT 06 NEW REPOSITORY**

新开源桌面工具可展开 Verilog、SystemVerilog、VHDL 和 Liberty 宏层级，交互定义电源域、供电集合、开关、隔离、保持、级联电平转换与电源状态表，并导入/导出 UPF 3.0/3.1 与 CPF 2.0/2.1。

对低功耗 RTL 设计与评审很实用：仓库附带混合层级示例和约 2,500 个测试，但当前验证主要是规范对照、参考文件与自身往返，不等同于主流商业 EDA 的签核。Python 3.10+ 可在 Windows、Linux、macOS 运行；VHDL 额外依赖 GHDL 与 ghdl-yosys-plugin。代码 Apache-2.0，但打包分发还要考虑依赖许可。

Apache-2.0 · Verilog / SystemVerilog / VHDL · UPF 3.1 · CPF 2.1

[原始来源](https://github.com/mikespyke17/power-intent-studio)

## OCBench：面向离线到在线控制的可扩展操控基准

**机器人学习评测 · OCT 05 NEW REPOSITORY · 仿真**

新公开基准提供 5 类环境、28 个操控任务，覆盖状态与像素观察、行为克隆与强化学习；接口兼容 Gymnasium，默认用 MJWarp 做 GPU 并行，也提供 CPU MuJoCo 变体和可自动下载/生成的数据集。

它适合比较数据驱动控制算法，示例可并行运行 1,024 个环境，CPU 版也能低门槛试用。必须明确：这是 UR5e + Robotiq 2F-85 描述上的仿真基准，没有真实机器人闭环或 sim-to-real 成功证据；像素版、GPU 吞吐和训练结果应按自己的硬件重新测。

MIT · Python 3.10+ · MuJoCo / MJWarp · 28 tasks · 仿真无实机

[原始来源](https://github.com/seohongpark/ocbench)

## MicroDuck HD1910M：板端运行链完整，但动作验收仍在仿真

**低成本机器人 / 强化学习 · OCT 06 NEW REPOSITORY · 仿真验证**

围绕 Radxa ZERO 3W、15 个飞特 HD1910M 舵机、BNO08x IMU 与 CSI 相机构建，公开 Rust 底层/后端、MuJoCo 与 RL 训练、四个 ONNX 动作模型、ARM64 运行包和 Android APK，并给出布线、零位、模型哈希和部署步骤。

可复现细节较多，但仓库自己也明确：当前起身与翻滚证据是 App 触发的独立仿真，其他倒地初态未全部通过，不能宣称实机或全工况验收；默认 API 无令牌，只应放可信局域网。Linux 板端需 glibc 2.35+、Rust 1.89 与实际校准文件；仓库未声明许可证，第三方权重再分发/商用也需逐项确认。

许可证未声明 · Radxa ZERO 3W · ARM64 · MuJoCo 验证 ≠ 实机验收

[原始来源](https://github.com/zhuoligetu123/microduck-hd1910m)

## 今日深挖：今日深挖：Power Intent Studio 把低功耗意图从 Tcl 文本变成可审查结构

它最有价值的地方，是把 RTL/Liberty 层级、电源域、隔离、保持和电源状态表放到同一个可视模型里，再导入导出 UPF/CPF；这让低功耗意图更容易进入代码评审和自动化回归。局限是当前证据主要来自规范对照、示例和自身往返测试，不等同于商业 EDA 的语义一致性或签核。下一步应选一个真实混合语言模块，在工具与现有 EDA 间双向往返，逐项核对层级绑定、域边界、隔离/保持条件和错误诊断，再决定是否进入正式流程。
