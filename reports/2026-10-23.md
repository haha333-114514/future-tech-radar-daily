## Verilator：用每线程进度字减少并行仿真的同步开销

**FPGA / SystemVerilog · OCT 23 MAIN · 非正式发行**

12:00 合入 043f7aa：每个工作线程拥有独占 cache line 的进度字，生产者用 release store 发布已完成任务位置，消费者用 acquire load 等待；避免为每条依赖更新共享计数器的读改写。与 21 日 $readmemh 功能、昨日 Yosys BTOR2 修复不同，这是多线程 HDL 仿真运行时的优化。

适合大设计、多核 CPU 上运行 Verilator 的人；LGPL-3.0 / Artistic-2.0 双许可，Linux/WSL 编译路径成熟，无 GPU 需求。主干同时改动任务调度、生成代码及线程回归相关文件，但不能由同步机制推断所有设计都提速，也没有本期核实的倍数。用同设计/编译器对比单线程与多线程、开启/关闭 trace 的耗时和结果一致性；固定并重建生成模型，别混用旧运行时。没有新增器件、综合、Fmax 或 LUT/BRAM 数据，本次未编译跑分或上板。

LGPL-3.0 / Artistic-2.0 · 多核 CPU · 减少同步 RMW · 非已证实倍数 · 仅仿真运行时 · 无新器件/PPA

## 信号与噪音

判断而非事实：‘已有模型接入统一工具链’常被高估为‘随便一台机器人零样本即用’。WALL-OSS-0.5 的模型故事不是今天才发生；这次值得看的是真正可加载的权重布局、处理器、相机/关节契约与训练入口。没有目标机器人数据、动作边界检查和实体测试，就不应把旧演示当新部署成绩。相同原则也适用于端侧算子融合：代码合入不自动证明兼容全部手机、速度翻倍或功耗下降。
