## LTX-2 的 motion_speed：慢动作是生成条件，不是改播放速度

**视频生成 · OCT 22 MAIN · 非正式发行**

今早 05:23 合入 Diffusers 7e4383c：新增正数 motion_speed，默认 1；模型位置时间轴按 frame_rate / motion_speed 条件化，文件播放帧率、音频长度仍按 frame_rate。示例在 24fps 下取 0.2，形成 5 倍慢动作的生成条件。相较 19 日的 LTX SDK 解码/内存更新，这次是新的运动控制接口。

适合视频创作与可复现的 LoRA 工作流。Diffusers 代码 Apache-2.0；示例的 LTX-2.5 22B Slow-Motion-Control LoRA 有门控许可，先核对模型授权。官方例用 BF16、CPU offload、VAE tiling 和 1920×1088；小尺寸效果较弱，未给出可保证的最低显存或 RAM。建议 CUDA 独立环境固定提交；CPU/MPS/XPU 写入示例不等于本次验证了可用速度。远离 1 的速度需相应训练的适配器，不能给任意基础模型加参数就承诺慢动作。两阶段生成都须传同一速度，否则第二阶段可能抵消效果。

## Yosys：只有一个元素的 memory，也要导出合法 BTOR2

**FPGA / 形式验证 · OCT 22 MAIN · 非正式发行**

今早合入的修复处理 write_btor 的零位宽地址：单元素 memory 的 ceil(log2(1)) 为 0，旧输出可能包含非法 bitvec 0、节点 -1。新实现把地址 sort 至少设为 1 位，并在明确目标位宽时把空操作数扩展为零常量。相较 20 日 GateMate I/O pad 修复，这是形式验证后端的边界正确性更新。

适合用 Yosys 接 btor2tools、rIC3 或做 refinement miter 的 HDL 开发者。ISC，CPU 工具链即可，Linux/WSL 易于复现；固定 234206e 或其合并提交。应分别检查 memory -nomap 与 memory_map 后的导出，验证单元素索引 0 和零扩展语义；未给目标位宽的零宽信号会报错，不能任意吞掉。没有新增器件、布局布线、时序或 LUT/BRAM 数据；合法导出不等于设计属性已经证明通过。本次未实际编译求解器或上板。

ISC · BTOR2 导出正确性 · 单元素 memory · 映射前后均涉及 · 无新器件/PPA 数据 · 未上板

## 今日深挖：一个元素的数组，为什么值得修形式验证工具？

数学上给 N 个元素编码需要 ceil(log2(N)) 位；N=1 时得 0。但 BTOR2 要求正位宽 sort，不能直接把 HDL 的空地址搬进文件。Yosys 这次不是给逻辑随意加状态：导出用至少一位地址，实际端口仍只访问索引 0；有明确目标宽度的空值用零常量表达，没有目标就拒绝输出。长期价值在于工具之间的语义契约：设计很小也可能碰到表示法的边界。建议用一元素数组延迟参考模型，分别导出保留 memory 和映射后的版本，再用解析器检查格式、求解器检查预期属性，并加上多元素对照。解析成功、属性成立、FPGA 能综合和板上时序达标是四件不同的事。本次阅读了补丁，没有代替你跑这些验证；这是建议的复现步骤，不是已通过的实验结果。
