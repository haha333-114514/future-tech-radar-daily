## RTX VSR Long Video：为 ComfyUI 长视频做磁盘分段超分

**超分辨率 · OCT 12 近期新项目 · 非今日发布**

这是 NVIDIA RTX VSR 的独立集成，不是新扩散模型：逐帧/分块处理，将临时编码段写入磁盘，再拼接输出并保留音轨，避免把整条未压缩视频留在 RAM；提供放大、去噪、去模糊和视频预览。仓库最近提交为 10 月 12 日，处于本期 72 小时研究窗口内。

适合已有 RTX 和 ComfyUI、处理长片时被内存卡住的人。代码 Apache-2.0，NVIDIA SDK/模型另有条款；需要兼容 CUDA/PyTorch、nvidia-vfx≥0.2 和 FFmpeg，NVENC 还要求对应编码器。当前仅 SDR 8-bit；H.264 NVENC 每轴上限 4096，更大输出需另选编码路径。未给显存/RAM 下限或对照基准，先用短片核对音画、帧率、细节和临时磁盘峰值；低 RAM 是架构目标，不是零内存或零磁盘成本。

Apache-2.0（集成代码） · NVIDIA RTX · SDK / FFmpeg · SDR 8-bit · 无统一硬件基准

[原始来源](https://github.com/tritant/ComfyUI_NVIDIA_RTX_VSR_Long_Video/tree/b20565455379998d3a22c07eb959d0a235034bde)

## ComfyUI：接入 MiniMax-H3 LightVAE，允许独立编码器/解码器

**图像生成 / 工作流 · OCT 15 MAIN BRANCH · 视频 VAE**

加载器识别 LightVAE Lite 中剪枝后只保留 shortcut 的编码模块，并按权重是否包含对应部分构建 encoder 或 decoder。相较昨日 0.40.0 正式版，这是今天主分支新增的 VAE 兼容能力，不应混写成该稳定版自带。

适合拆分视频编码、采样、解码或评估轻量 VAE 的工作流作者。GPL-3.0 代码，VAE 权重许可另查；Python/PyTorch，GPU 与显存需求取决于权重精度、分辨率和时序长度。此次没有端到端速度、质量或显存节省数字，“Light”不等于已证明低显存。固定提交和原始 VAE，对照时间一致性、重建误差、峰值内存及独立加载行为。

## Verilator：少量激活逻辑直接串行执行，避免唤醒工作线程

**FPGA / SystemVerilog · OCT 15 MAIN BRANCH · 多线程仿真**

为触发条件记录静态逻辑代价；当当前被触发的宏任务总代价很低时，在调用线程按拓扑顺序执行，仅处理激活任务，不唤醒其余线程。它不同于前期交叉覆盖支持和昨日 GHDL TEXTIO 修复，是运行时调度优化。

适合多线程 RTL 仿真中大量周期只有少量逻辑活动的团队。Linux/WSL CPU 源码构建，LGPL-3.0 或 Artistic-2.0；没有指定器件、综合资源或板上时序变化，也未给通用仿真加速倍率。固定设计、线程数、激励和 tracing 配置做墙钟时间/正确性对照；profiling 模式禁用此串行捷径，测试也可用 VL_THREADS_SERIAL_COST=0 强制比较并行路径。

LGPL-3.0 / Artistic-2.0 · CPU · 触发代价 / 调度 · 仿真性能 ≠ FPGA Fmax

## Isaac Lab：BAM 舵机模型与 MicroDuck 平地/粗糙地形任务

**低成本机器人 / 强化学习 · OCT 15 MAIN BRANCH · 仿真验证**

将小型智能舵机的电压、摩擦、供电下垂、指令延迟及齿隙带入 Newton/MJWarp，提供 MicroDuck 14 舵机任务。维护者在 RTX 5090、4096 环境的特定测试中，合并模型变化通知后 step 中位数由 20.8ms 降至 15.9ms；这不是所有机器人任务的加速结论。

适合低成本双足 sim-to-real 研究，区别于昨日 G1 远程实机配方。BSD-3-Clause 代码，USD/舵机辨识数据需按各自许可与来源核对；要求 Newton+MJWarp，CPU MuJoCo/PhysX 不支持这套驱动。维护者给出记录摆运动与模型对照、仿真回放及边界测试，但没有新增 MicroDuck 实机行走成功率，也未给最低显存、完整 BOM 或新增训练权重。现有 checkpoint 能运行不等于动力学完全等价，更不等于可直接上机。

BSD-3-Clause（代码） · Newton / MJWarp · RTX 5090 验证 · 仿真 / 记录轨迹对照 · 非新增实机结果

## LangChain：逐工具调用暂停审批，附带响应 schema

**Agent 工具审批 · OCT 15 RELEASE · LangChain 1.4.6**

HumanInTheLoopMiddleware 新增可选 interrupt_mode=per_call：每个被管控的调用单独暂停，审批按 interrupt ID 回答，并在保存前校验允许的决定及 Pydantic 参数。默认仍为 batched；LangGraph 下限升至 1.2.12，异步运行要求 Python≥3.11。

适合实现审批卡片、文件写入/外发控制的 Agent 应用。MIT，CPU 可跑编排，模型 API 成本或本地推理算力另算；它不是权限沙箱或整批事务。原始 JSON schema 工具的编辑参数未获同等校验；一次恢复多个审批若部分无效，其他工具可能已执行，重试可能重复副作用。先在假工具上验证拒绝、编辑、恢复和幂等，不要用真实删除/发送操作试错。

MIT · 逐调用审批 · 可选启用 · schema 校验 ≠ 沙箱 / 事务

## llama.cpp：修复 CPU SET_ROWS 多线程转换缓冲越界

**本地 LLM 推理 · OCT 14 MAIN BRANCH · 非今日发布**

SET_ROWS 原按单任务规划临时缓冲，但混合图中每个线程都可能执行并使用自己的 F16→F32 转换行，导致线程 0 以外写出工作区；提交改为按线程数规划。它不是昨天 Ollama CUDA 内核移植，也不同于前期 FA 回退修复。

适合维护 CPU 推理、自定义 GGML 图和多线程部署的人。MIT，普通 CPU 即可复现相关路径；RAM 与量化取决于模型，补丁不代表更低内存或普遍加速。没有 CVE、利用性或影响全部模型的证据，不将其夸大为已确认远程漏洞。固定提交，用相同模型和图比较单/多线程结果，并在开发构建中配合内存检查；确认发行构建包含补丁后再推广。

MIT · CPU · F16→F32 · 工作缓冲 · 正确性修复 · 非通用性能更新

## 今日深挖：逐工具审批：真正难的是恢复后的副作用，而不是弹出确认框

事实：LangChain 的 per_call 把审核对象从整轮数组改成有独立 ID 与响应 schema 的工具调用，Pydantic 工具的错误编辑可在保存前拦截；未被管控的工具仍可能立即执行。判断：这对可靠 Agent 比再多一个演示更重要，因为审批、执行和重试的边界终于可以独立测试。局限：多条审批一起恢复时，某条校验失败不保证其余工具尚未执行，整批重试可能造成重复发送或重复写入；原始 JSON schema 的编辑校验也有缺口。下一步：先用只记录日志的假工具，覆盖批准/拒绝/错误编辑/断线恢复，客户端先校验 schema，必要时逐个回答；真正有副作用的工具再加幂等键和执行审计。它仍不替代最小权限、工作区隔离、超时或回滚。
