## InvokeAI 7 alpha 2：GGUF 视觉模型、AMD ROCm 10 与显存预留一起推进

**图像 / 视频生成 · OCT 11 ALPHA RELEASE**

新版支持 krea2 Q8_CR、Ideogram 4 与 ERNIE-Image 的 GGUF transformer，补强 MiniMax H3 与 LTX-2 视频输入，引入 reserve_vram_gb 为中间张量预留显存；多用户部署可改用 MySQL/MariaDB，AMD 路径升级到 ROCm 10。

## llama.cpp b11552：修复固定 slot 请求污染正在生成的上下文

**本地 LLM 推理 · OCT 11 PRE-RELEASE · 相较 10/10 有新增**

当请求指定一个忙碌的 id_slot 时，旧逻辑会在等待前仍更新该 slot 的 prompt cache；若 RAM cache 命中更好上下文，正在生成的请求可能继续在错误上下文上运行。新版让忙碌 slot 保持不动，后来的请求等待。

这是多会话 llama-server 的正确性修复，比单次 tokens/s 更重要：错误可能不是显式崩溃，而是生成内容悄悄串上下文。相较昨天的 SYCL MXFP4 性能改动，这是新的服务端并发边界。发布仍是每日预发布，但提供 CPU、CUDA、ROCm、Vulkan、OpenVINO、SYCL、Snapdragon、iOS/Android 构建；生产用户应固定版本并用并发固定-slot、cache 命中和长上下文压力测试复现。

MIT · 桌面 / 服务器 / 移动端 · 并发正确性 · 预发布

[原始来源](https://github.com/ggml-org/llama.cpp/releases/tag/b11552)

## Ollama 0.40.3：暂停每次请求触发的后台模型升级检查

**本地 LLM 推理 · OCT 11 PRE-RELEASE · 0.40.3**

维护版暂停本地模型兼容性后台升级流程，因为它会给每个请求增加固定开销，在 embeddings 等高请求量场景尤其明显；同时移除启动 Claude/Codex 时已经过时的连接器与 service tier 警告。

它适合用 Ollama 做本地 embedding 服务或高频 API 网关的人，改动针对请求路径开销，不代表单次生成内核变快。模型 RAM/VRAM 仍由模型大小、量化与上下文决定，Windows、Linux、macOS 均可用；这是预发布版，应比较升级前后的 QPS、P95/P99、冷启动与模型兼容，而不是只看交互聊天体感。

MIT · Windows / Linux / macOS · 高频请求路径 · 预发布

[原始来源](https://github.com/ollama/ollama/releases/tag/v0.40.3)

## chaiNNer：修复 TensorRT 超分缓冲区类型与固定尺寸切片

**超分辨率 · OCT 11 MAIN BRANCH · TensorRT**

主分支现在按 engine 实际输入/输出 tensor dtype 分配和转换 host buffer，避免 FP32 ONNX 以 FP16 构建时出现半尺寸缓冲区；固定 shape engine 改用精确 tile，并检查 set_input_shape，另对计算能力低于 7.5 或驱动低于 580 的 CUDA 13/TensorRT 包显式禁用。

这直接影响本地 TensorRT 超分是否算对、是否在不支持的显卡上误启动。适合 NVIDIA RTX/Turing 及更新架构用户在隔离环境验证；它是主分支提交，不是正式 release，也没有统一画质或吞吐数据。应固定同一模型、tile、重叠和输入，比较输出像素、显存、耗时与边缘接缝；老 GPU 不应绕过新门槛强装。

GPL-3.0 · NVIDIA · compute capability 7.5+ · TensorRT / CUDA 13 · 主分支

## vLLM：MiniMax-M3 稀疏注意力 prefill 改用 E4M3 query

**LLM 推理服务 · OCT 11 MAIN BRANCH · 相较 10/10 有新增**

主分支更新 Blackwell sm100 的 MSA 依赖，让 MiniMax-M3 的 MSA prefill 以 E4M3 query 进入稀疏注意力，并补对应 kernel 测试；同一窗口还修复跨 KV cache group 的推测 block 预留。

## Verilator：修正 suspendable process 中整块 unpacked array 的 NBA

**FPGA / SystemVerilog · OCT 11 MAIN BRANCH · 相较 10/10 有新增**

当可挂起进程或 fork 对整个 unpacked array 做 nonblocking assignment 时，旧 shadow-variable 策略的 pre 逻辑可能在恢复后覆盖新值；新版改用 unique flag 路径并加入回归。同一窗口还修复 descending $readmem/$writemem、按名 disable 的 function port 与参数特化命名内部错误。

这对含协程式 testbench、fork/join 与数组 NBA 的 SystemVerilog 验证环境是明确语义修复。它仍是主分支、尚无正式 release；也没有综合、时序或 FPGA 资源数据，因为 Verilator 是仿真/编译器而非实现工具。应固定 commit 跑最小复现和完整回归，尤其比较数组更新时序与其他仿真器结果。

LGPL-3.0 / Artistic-2.0 · SystemVerilog 仿真 · 主分支 · 带回归测试

## 信号与噪音

判断：今天 Trending 里的各类 agent skills / knowledge-work plugins 很醒目，但提示词、模板和精选技能集合本身不等于 Agent 具有权限隔离、可重复评测或失败恢复。它们可以作为工作流参考入口，只有回到具体工具与原仓库验证执行边界、版本、测试和数据来源后，才值得当成技术信号。
