## MOSS-Image：5B DiT 的 Base/SFT、文字渲染与 JSON 布局控制

**图像生成 · OCT 16 发布 · 非当日发布**

OpenMOSS 公开模型与推理代码，主打较长提示词、图中文字及结构化布局。Base 用于适配研究，SFT 用于经过后训练的生成；默认是 50 步 flow-matching Euler，并非宣传帖里所有第三方少步蒸馏版本的同一基线。

适合本地海报、中文文字和空间布局实验。代码与官方权重为 Apache-2.0；Python/PyTorch、Gradio/ComfyUI 入口已给出，文本编码与 VAE 的成本仍需计入。官方提供 GPU 常驻、组件搬移和 sequential 三种模式，但未给适用于所有 checkpoint/分辨率的最低显存表。先固定 SFT 与官方采样参数，对比文字错误率、布局偏差和 RAM/VRAM；低显存模式以速度换空间，不能只按 5B 主干估计整栈。

Apache-2.0（官方代码/权重） · 5B 主干 · 50 步默认采样 · 布局 / 文字 · 显存下限未统一给出

[原始来源](https://github.com/OpenMOSS/MOSS-Image/tree/c1355e6b1986dfe8fba3c0455783a05899212342)

## REKI：2.4B VLA 用缓存 register tokens 保存近期观测

**具身智能 · OCT 16 首发代码 · 非当日发布**

Kyutai 以 Qwen3.5-2B VLM 加 flow-matching 动作专家，每帧保存 32 个 register tokens；公开预训练/基准微调权重、推理和评测入口。作者报告 H100、两路 256² 图像、编译后预测动作 chunk 为 21.8ms，不能转成任意消费卡或机器人闭环帧率。

适合可复现 VLA 与短期记忆研究。Linux x86-64、CUDA 12、pixi/Python 3.12；最低显存及机器人完整成本未给出。代码 MIT，部分第三方 Apache-2.0；权重 CC-BY-NC-SA 4.0，数据各自保留许可。Panda/ALOHA/PandaOmron 权重对应仿真基准，另有实机服务接口；项目报告实机实验不等于所有平台可直接部署。首发 README 明确预训练代码/数据流水线仍待后续发布，不能写成完整预训练已可重跑；先做离线回放与仿真，再按自有机器人数据微调。

代码 MIT / 部分 Apache-2.0 · 权重 CC-BY-NC-SA 4.0 · H100 性能报告 · 非通用实机保证

[原始来源](https://github.com/kyutai-labs/reki/tree/12dd1e24acfc01c817e03ecd43f37cc5f9f6b2d1)

## Diffusers：FLUX.3 原生扩写块与模块化加载说明补齐

**扩散模型工具链 · OCT 17 MAIN BRANCH · 相较 10/16 新增**

## Isaac Lab：reset 后不再读回上个 episode 的接触缓冲

**机器人仿真 · OCT 17 MAIN BRANCH · reset 正确性**

修复 OVPhysX 与 PhysX 的 ContactSensor：部分环境 reset 后、下一物理步前读 observation，旧力、摩擦历史或接触点会重新灌入。新内核按 reset 时间戳跳过，保持零力/历史及 NaN 接触点直到传感器下次更新。

适合并行 RL、接触奖励和重置观测研究。BSD-3-Clause；维护者在 Isaac Sim 6.1、OVPhysX 0.6.4 的 CPU/CUDA 与聚焦测试中复现并验证，不是实体传感器测试。所需 GPU/RAM 随仿真规模变化，无新最低显存结论；重跑局部 reset、CUDA graph 回放和 reward 检查，不能把重置后的 NaN 接触点当成故障数据擅自填入旧值。与此前 MicroDuck 建模不同，这是跨 episode 状态隔离。

BSD-3-Clause · PhysX / OVPhysX · 仿真传感器 · reset 后观测 · 有聚焦回归

[原始来源](https://github.com/isaac-sim/IsaacLab/commit/0ab97e9c811a7ddabc4fcc08e32ca48b5722d15a)

## LeRobot：Feetech 与 Dynamixel 统一到 rustypot 串口总线

**机器人 / 舵机总线 · OCT 16 MAIN BRANCH · 非当日发布**

SerialMotorsBus 以 Rust 协议实现替代厂商 Python SDK 表面，事务期间释放 GIL；按精确舵机型号处理寄存器、符号、字节序、校准及扭矩。旧家族类保留为弃用别名，新增 serial-motors extra，依赖 rustypot≥1.13.1。

适合 SO-100/101、LeKiwi 等串口执行器链路维护者。Apache-2.0 代码，需电脑/板端、兼容串口适配器及实际舵机；无新 GPU 要求或 BOM 成本数据。提交覆盖模型识别、失联时释放端口、尽量关闭各电机扭矩等边界，但内存总线 mock 不能代替实机时延与安全验收。保留旧环境和校准备份，先无负载验证型号、方向、断开与失败清理，再迁移整机；没有通用加速倍率。

## Yosys：FSM 提取保留 next-state 含 undef 的转移

**FPGA / 综合优化 · OCT 16 MAIN BRANCH · 非当日发布**

更新 fsm_extract，对部分位未定义的 next state 按已定义位匹配可选状态，避免直接丢失相关转移，并加入 fsm-undef-next 回归。与 14 日 mcm 常数乘法优化不同，这是状态机提取语义的正确性更新。

## 今日深挖：REKI 的记忆在动作专家里：小缓存不等于低复现成本

事实：每帧的少量 register tokens 留在动作专家缓存，后续动作可读取近期上下文，而不是反复把所有历史图像送入 VLM；首发 API 要求每个 episode 开始调用 reset 清缓存。作者在 H100 编译路径报告较低额外读取开销，属于特定测试而非任意硬件保证。判断：长期价值在于可以消融“历史是否真的帮助减少动作振荡”，而不只比较模型参数。局限：公开数据来源、开放权重和完整可重跑预训练是三件事，首发快照仍留有后续代码发布项，权重还有非商业许可限制。下一步先固定初始 commit 和基准权重，验证相机方向、state/action 顺序与归一化；比较有/无记忆、跨 episode 清缓存及长任务失败模式，再考虑自有硬件微调，不能将仿真成功率直接套到实机。
