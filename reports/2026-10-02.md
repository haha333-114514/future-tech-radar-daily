## mise v2026.10.0：补上 .tool-versions 信任与签名身份校验

**开发环境 · OCT 02 SECURITY RELEASE（中国时区）**

带 inline options 的 .tool-versions 现在必须显式 trust，避免恶意 api_url 把 GITHUB_TOKEN 发往其他主机；keyless cosign 会核对固定 signer identity，GitHub attestation workflow 匹配也改为路径段锚定。

这是实际供应链修复，不只是新功能。使用 mise 管理 GitHub/aqua 工具和 CI 安装的用户应尽快升级并审计已信任项目；MISE_SAFE=1 仍会跳过 trust 检查，不应作为日常默认。版本还修复 musl、SLSA lock 和 backend switch。

MIT · Windows / Linux / macOS · GHSA · cosign · attestation

## uv 0.12.22：workspace group 信息进入锁文件

**Python 工具链 · OCT 02 RELEASE（中国时区）**

锁文件开始记录 workspace member 的默认 dependency groups 与 Python 要求，frozen sync 会使用各成员记录的默认组；重新锁定时也会校验未变化 requirement 的既有 hash。

这让 monorepo 的 CI 与本地环境更接近可复现，但不是自动安全审计。版本加入 CPython 3.10.22–3.14.8 和 UV_PYTHON_ARCH，覆盖 Windows ARM64 等场景；构建 uv 本身的最低 Rust 版本升至 1.97，使用源码构建者要先升级工具链。

Apache-2.0 / MIT · Windows / Linux / macOS · lock hash · workspace groups

[原始来源](https://github.com/astral-sh/uv/releases/tag/0.12.22)

## Ruff 0.16.10：不在不可信工作区自动运行 uv format

**Python 工具链 · OCT 02 RELEASE（中国时区）**

Ruff server 停止在未信任工作区触发 uv format，并降低 diagnostics 内存；新增 Python 3.15 支持和 context-manager iterator annotation 预览规则。

编辑器打开陌生仓库时，自动调用外部工具会扩大执行面，这项默认行为修正比新增 lint 规则更重要。预编译包覆盖 Windows、Linux、macOS 与多种架构；自己编译则要求 Rust 1.97+。

MIT · Windows / Linux / macOS · untrusted workspace · LSP

[原始来源](https://github.com/astral-sh/ruff/releases/tag/0.16.10)

## Cline CLI 3.0.68：长时间 Agent Team 状态不再无限膨胀

**编码 Agent · OCT 02 RELEASE**

团队成员流式输出时不再为每个 chunk 重写整份 team state；旧行为会让运行逐渐变慢，并让 ~/.cline/data/db/teams.db 增长到 GB 级。升级后首次打开会自动 compact 既有数据。

这直接影响多 Agent 长任务的成本与失败恢复，而不是单纯换模型目录。自动压缩前仍应备份关键会话；模型目录默认值的变化不代表团队协作质量提升，权限、工作区冲突和任务回滚仍需单独设计。

Apache-2.0 · CLI · 本地状态库 · Agent Team · 自动 compact

[原始来源](https://github.com/cline/cline/releases/tag/cli-v3.0.68)

## Cua Sandbox 0.9.0：默认改为本地执行

**计算机使用 Agent · OCT 02 RELEASE（中国时区）**

Sandbox.create 改为默认 local，底层迁移到统一 Cua SDK，并移除 localhost module、computer_server 以及旧 http/local/websocket transports。

默认本地有利于离线和数据边界，但这是 breaking change：依赖远端 sandbox 或旧 transport 的代码必须显式 local=False 并迁移 API。运行位置改变不等于权限自动收紧，仍要限制挂载目录、网络与桌面控制能力。

MIT 为主 · 组件许可分区 · 本地 sandbox · breaking API change

[原始来源](https://github.com/trycua/cua/releases/tag/sandbox-v0.9.0)

## 今日深挖：今日深挖：mise 的修复说明“签过名”不等于“签对人”

旧 keyless cosign 路径只确认 bundle 能追溯到 Fulcio，任何 GitHub Actions workflow 都可能拿到这种证书；新版本才把 registry 声明的 signer identity、issuer 和 workflow 信息真正用于核验。配合 .tool-versions trust 修复，这提醒我们供应链验证至少要回答三个问题：谁签的、为哪个仓库/工作流签的、项目配置是否被用户信任。下一步应升级 mise、清点 trust 列表，并复核 MISE_SAFE 与 CI 中的例外。
