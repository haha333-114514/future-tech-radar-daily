## HyperFrames v0.8.99

**视频工具 · SEP 30 RELEASE · TRENDING**

把 HTML、CSS、媒体和可寻址动画确定性渲染成 MP4 的开源框架，提供本地 CLI 与面向 Agent 的工作流。新版本修复 Studio 中拖拽、旋转、裁剪、时间线移动和场景视频帧同步，并避免读取半写入的项目文件。

## Open RF IP：可移植 DDS / FMCW Chirp

**FPGA / SystemVerilog · SEP 30 PHYSICAL VALIDATION**

一套厂商无关的 SystemVerilog DDS/NCO 与 FMCW chirp 软核，在 Lattice CrossLink-NX LIFCL-40-EVN 上以 12 MHz 实测；通过 FT2232H 读取前 1,024 个 I/Q 样本，与独立 Python 模型逐样本完全一致。

证据链难得完整：147 个测试、16 个 RTL/板卡运行器，公开原始二进制和 CSV；实现占 349 COMB、155 FF、3 EBR、0 DSP。nextpnr 给出的约 198.93 MHz 只是估算而非实测上限，验证也仅覆盖数字输出前缀，尚未测 DAC、频谱与相噪；仓库未声明许可证，复用前必须先确认授权。

CrossLink-NX LIFCL-40 · Verilator · Yosys · nextpnr · 实板 1,024 样本 bit-exact

[原始来源](https://github.com/Cortex-Wave-Research/open-rf-ip)

## VWW_B8：INT8 MobileNetV1 全网络上板

**FPGA / 边缘视觉 · SEP 30 VERIFIED PACKAGE**

在 Kintex UltraScale+ xcku3p 上实现 96×96 的 INT8 MobileNetV1 人体存在检测，公开 bitstream、UART 程序、XSA 与模型哈希；20 张实图上板时，620 个逐层 CRC 和 80 个最终 INT8 输出均与 TFLite 参考一致。

核心推理约 33.55 ms/图，但 115200 波特率 UART 上传与回传平均约 4.65 秒；20 张样本只得到 85% 准确率、70% person recall，不能代表通用精度。流程依赖 Vivado/Vitis/HLS 2020.1 和匹配板卡，本次包保留既有验证而非重新综合；未声明许可证，也未提供浮点训练权重。

Kintex UltraScale+ · INT8 · 31 operators · 实板逐层 CRC 一致

[原始来源](https://github.com/Mosen-zhou/VWW_B8)

## JEV Sees v0.1.0

**具身智能 · SEP 30 EXPERIMENTAL**

一个面向机器人场景状态的视觉前端：本地 YOLO/CLIP 可处理图像、视频和 RGB-D，并维护目标跟踪与场景状态；在 RTX 4070 Ti Super 上，YOLOv8s 框检测约 19.5–22 ms，完整 RGB 流水线约 92–103 ms。

它适合探索‘感知结果如何进入具身决策’，但不是 VLA，也没有公开真实机器人闭环验证。无 API key 时只能运行本地感知与跟踪，结构化判断依赖远程 JEV 服务；RGB-D 路径约 379–408 ms，首次使用还需下载权重。因此当前应视为实验组件，而非离线可部署的机器人栈。

MIT · Python 3.10+ · YOLO / CLIP 本地感知 · 无实机闭环证据

[原始来源](https://github.com/CharlesFeng0314/JEV_sees)

## vLLM：Kimi-K3 推测解码与 SM120 优化

**LLM 推理服务 · OCT 01 MAIN BRANCH**

主分支加入 Kimi-K3 的 FlashInfer speculative KDA 后端、面向 SM120 的 occupancy-adaptive Triton split-K，并减少流水线并行中已离开引擎请求的 sampled-token 广播；容器构建也开始预编译 Python bytecode。

这是一组面向高吞吐服务端的细粒度更新，适合追踪新模型、Blackwell 级 GPU 和分布式推理的落地节奏；它不是正式 Release，也没有随提交给出统一端到端吞吐基准。生产环境应固定提交、复跑自己的延迟与并发测试，不能把单项内核优化直接等同于整体提速。

## 今日深挖：今日深挖 · Open RF IP

这个项目的长期价值不在仓库热度，而在验证方式：DDS/NCO 与 FMCW chirp 的 Python 参考、cocotb/Verilator 回归、Yosys/nextpnr 实现和 CrossLink-NX 物理采样被串成同一条可审计链。默认配置用 32 位相位累加器、10 位 LUT 地址和 14 位有符号 I/Q，在 12 MHz 下生成 500 kHz 到 2 MHz、10,000 样本的 chirp；板上抓取的前 1,024 个样本与独立模型零偏移、零误差。局限也必须保留：物理验证只覆盖数字路径和采样前缀，约 198.93 MHz 是工具估算而非测得 Fmax，生成 bitstream 未纳入仓库，且没有许可证。建议下一步先离线重跑 147 个测试并从源码重建 bitstream，再改变 chirp 配置与时钟做多组抓取；真正用于 RF 系统前，还要补 DAC、滤波、频谱纯度、杂散和相噪测量，并让维护者明确许可。

[查看原始项目](https://github.com/Cortex-Wave-Research/open-rf-ip)
