## Cua Driver：把‘后台点击’失败改成显式拒绝

**计算机使用 Agent · OCT 08 MAIN BRANCH · DAILY TRENDING**

今天的主分支连续修复后台 GUI 操作：当 LibreOffice 无法接收后台像素点击、Chromium 地址栏无法安全后台提交时直接拒绝；run_actions 也增加陈旧目标恢复、同名元素按角色消歧，并修复宿主机通过 HTTP 代理连接。

## claude-mem v13.34.2：为提示缓存一致性撤回历史裁剪

**Agent 记忆 · OCT 06 RELEASE · DAILY TRENDING**

修复 OpenRouter、Gemini 等 OpenAI 兼容观察器中的回归：此前每轮改写已发送的旧工具消息，导致提示前缀不再一致、缓存无法复用；新版停止在同一 generation 内裁剪历史，让后续请求只追加而不改写已发送前缀。

这是 Agent 记忆系统常被忽略的工程问题：压缩上下文不一定省钱，若破坏 provider 的 prefix cache，反而会重复计费与增加延迟。项目需要 Node.js 20+，可本地观察或接 OpenRouter/Gemini/Anthropic；官方明确没有生产成本测量，且回归套件 881 项仍有 1 项既有 socket timing 失败，因此应先对自己的长会话测缓存命中、token 与隐私边界。

Apache-2.0 · Node.js 20+ · 前缀缓存 · 成本未实测

[原始来源](https://github.com/thedotmack/claude-mem/releases/tag/v13.34.2)

## 今日深挖：今日深挖：Agent 记忆的成本问题，本质上是前缀不变性

claude-mem 这次回退历史裁剪，说明上下文压缩并不天然等于成本下降：只要系统改写已经发送过的前缀，provider 的提示缓存就可能整体失效，后续每轮都重新计算。长期更可靠的设计应把不可变历史、可追加记忆和可重新生成的摘要分开，并为缓存命中、token、延迟和隐私建立真实测量。该项目没有给出生产成本结论，因此下一步应在自己的长会话上做 A/B：固定任务与模型，对比缓存命中率、输入 token、首 token 延迟、摘要偏差和本地保存边界。

[查看原始项目](https://github.com/thedotmack/claude-mem/releases/tag/v13.34.2)
